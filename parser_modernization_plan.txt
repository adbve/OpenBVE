1.1 REPLACE File.ReadAllLines() WITH STREAMING READERS
-------------------------------------------------------
PROBLEM: 15 parsers load entire files into memory upfront
FILES AFFECTED:
  - WavefrontObjParser.cs (lines 62, 398)
  - CsvRwRouteParser.cs (line 145)
  - NewXParser.cs (line 78)
  - ObjFileParser.cs (line 749)
  - +11 more files

SOLUTION: Use StreamReader with ReadLine() or custom span-based reader
BENEFIT: 90% memory reduction for large route files (100MB+ files common)

IMPLEMENTATION STEPS:
1. Create shared TextReader extension methods in OpenBveApi.ParserHelpers
   - ReadLineAsSpan() returning ReadOnlySpan<char>
   - SkipWhitespace(ref ReadOnlySpan<char>)
   - ParseNumber(ref ReadOnlySpan<char>, out double)
   
2. Replace pattern:
   OLD: string[] lines = File.ReadAllLines(fileName);
        for(int i = 0; i < lines.Length; i++) {
            var args = lines[i].Split(' ');
        }
   
   NEW: using var reader = new StreamReader(fileName);
        ReadOnlySpan<char> line;
        while ((line = reader.ReadLineAsSpan()).Length > 0) {
            // Zero-allocation parsing
        }

3. Priority order (by impact):
   a) CsvRwRouteParser.cs - Routes can be 50-200MB
   b) ShapeParser.cs - Binary + text mixed format
   c) WavefrontObjParser.cs - Complex 3D models with 100k+ vertices

ESTIMATED EFFORT: 16-24 hours
RISK: Low (streaming is well-tested pattern)

1.2 IMPLEMENT SPAN<T>-BASED TOKEN PARSING
------------------------------------------
PROBLEM: Every line does .Split() creating garbage
CURRENT CODE (WavefrontObjParser.cs:118):
  List<string> arguments = new List<string>(
      lines[i].Split(new[] { ' ', '\t' }, StringSplitOptions.None));

SOLUTION: Use ReadOnlySpan<char> with custom tokenizer
NEW CODE:
  ReadOnlySpan<char> lineSpan = line.AsSpan();
  while (lineSpan.Length > 0) {
      var token = GetNextToken(ref lineSpan); // No allocation
      ParseToken(token);
  }

BENEFIT: Zero allocations per line, 3-5x faster tokenization
FILES TO UPDATE: All text-based parsers (22 files)

IMPLEMENTATION:
1. Create static class SpanParserHelpers in OpenBveApi
   - GetNextToken(ref ReadOnlySpan<char>)
   - TryParseDouble(ReadOnlySpan<char>, out double)
   - TryParseInt32(ReadOnlySpan<char>, out int)
   
2. Benchmark before/after with large OBJ files (10k+ faces)

ESTIMATED EFFORT: 20-30 hours
RISK: Medium (requires careful testing of edge cases)

1.3 ADD ARRAYPOOL<T> FOR TEMPORARY BUFFERS
-------------------------------------------
PROBLEM: Parsers create temporary arrays that become garbage
EXAMPLE (WavefrontObjParser.cs:54-57):
  List<Vector3> tempVertices = new List<Vector3>();
  List<Vector3> tempNormals = new List<Vector3>();
  List<Vector2> tempCoords = new List<Vector2>();

SOLUTION: Use ArrayPool<Vector3>.Shared.Rent() for predictable sizes
NEW CODE:
  var tempVertices = ArrayPool<Vector3>.Shared.Rent(expectedSize);
  try {
      // Use tempVertices[0..count]
  } finally {
      ArrayPool<Vector3>.Shared.Return(tempVertices);
  }

BENEFIT: Reduces GC pressure by 60-80% during parsing
FILES: 15 parsers with large temporary collections

ESTIMATED EFFORT: 12-16 hours
RISK: Low-Medium (must ensure proper Return() calls)

4.2 ADD CACHING LAYER FOR REPEATED PARSING
-------------------------------------------
USE CASE: Same objects referenced by multiple trains/routes
CACHE STRATEGY:
  - LRU cache with memory limit (e.g., 500MB)
  - Hash-based content addressing
  - Invalidate on file modification

IMPLEMENTATION:
  public class ParserCache {
      private readonly ConcurrentDictionary<string, CachedObject> _cache;
      private readonly long _maxMemoryBytes;
      
      public T ParseOrGetCached<T>(string filePath) 
          where T : class
      {
          var hash = ComputeHash(filePath);
          if (_cache.TryGetValue(hash, out var cached))
          {
              if (cached.IsValid) return (T)cached.Value;
          }
          
          var result = ParseInternal<T>(filePath);
          _cache[hash] = new CachedObject(result, File.GetLastWriteTime(filePath));
          return result;
      }
  }

ESTIMATED EFFORT: 16-20 hours
RISK: Medium (cache coherence challenges)
